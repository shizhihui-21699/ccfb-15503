# 隐私保证与证据边界

本文档精确说明 powfence 提供什么保证、在什么假设下成立、用什么证据支撑，
以及**不**覆盖哪些攻击。部署方应把它作为安全评审的主文档。

## 1. 威胁模型

- **受害者**：在共享物理机上运行密钥相关运算（非对称解密/签名、对称密钥
  调度等）的租户工作负载。
- **攻击者**：同一物理机上的另一个租户，只能通过 powfence 的租户 API
  观测，拿不到宿主机特权、不能直接读 `energy_uj` / `scaling_cur_freq`。
- **攻击类别**：
  - 功耗侧信道（Platypus 类）：密钥内容改变封装能耗，统计区分操作类别；
  - 频率侧信道（Hertzbleed 类）：密钥内容改变 DVFS 频率，时间/频率统计
    区分操作类别。
- **攻击者能力假设**：可选择观测时机、可在 epoch 预算内持续轮询、知道
  防护算法与全部参数（Kerckhoffs 原则），唯一未知的是拉普拉斯噪声的
  实时随机抽取。

## 2. 形式化声明（signal_bounded 模式）

### 2.1 邻接关系

两个工作负载 $W, W'$ 互为**邻接**，当且仅当它们的差别仅为一次受保护
密码操作的密钥材料（其余指令、数据、调度完全相同）。

### 2.2 有界影响假设

设硬件实测得到：一次密钥操作在一个聚合窗口内能引起的

- 能量增量最大变化为 $\Delta_E$（`signal_max_delta_joules`），
- 窗口平均频率最大变化为 $\Delta_F$（`signal_max_delta_mhz`）。

管线中的残差裁剪保证：邻接工作负载在进入 DP 机制前的输入之差
$|x(W)-x(W')| \le \Delta$。该假设的成立依赖
[`CHARACTERIZATION.md`](CHARACTERIZATION.md) 的实测流程并保留安全余量。

### 2.3 拉普拉斯机制定理

对输入 $x$ 释放 $M(x) = x + \mathrm{Lap}(0, b)$，其中
$b = \Delta/\varepsilon$，则对任意输出集合 $S$：

$$
\frac{\Pr[M(W)\in S]}{\Pr[M(W')\in S]} \le e^\varepsilon
$$

即**每次窗口释放满足 $\varepsilon$-差分隐私**。代码中该机制位于
`internal/dp/dp.go` 的 `Laplace` / `LaplaceScale`，灵敏度选择位于
`EnergySensitivityJ` / `FrequencySensitivityMHz`，与定理一一对应。

### 2.4 顺序组合

同一租户在一个 epoch 内取得 $k$ 次释放，每次 $\varepsilon_i$，则
整体为 $(\sum_i \varepsilon_i)$-DP。`dp.Ledger` 在每次释放前记账，
超支即拒绝；策略加载时 `policy.validate` 预先证明最坏情况下
（窗口数上限 × 单次 ε × 预算份额）不会超过 epoch 预算。

能量与频率两个机制通过 `budget_share` 显式分割预算，份额之和 ≤ 1，
因此组合后的总消耗仍在公布的 epoch 预算内。

### 2.5 后处理不消耗预算

量化、非负截断、频率上限截断、`average_power_watts` 的派生，都是
DP 输出的确定性后处理，不增加隐私损失（DP 后处理定理）。粗量化还
独立贡献一个近似均匀的舍入误差，实测中它是额外的攻击者噪声。

### 2.6 full_range 模式（无模型声明）

当无法完成硬件表征时，可把 `dp_mode` 设为 `full_range`：灵敏度取
物理包络（封装功耗上限 × 窗长 / 最大频率）。此时 DP 声明**不依赖**
2.2 的实测假设，但噪声尺度通常大到监控效用显著下降，作为备选档位。

## 3. nominal-only 频率的独立论证

`expose_nominal_only` 不依赖 DP：每个窗口返回同一个静态标称频率。
输出随机变量与当前工作负载相互独立，$I(\text{secret}; \text{output})=0$，
Hertzbleed 类区分统计量在数学上无法构造。自测中该模式的频率 AUC
恒为 0.5、d' 恒为 0。

## 4. 实证证据（自测）

`powfence-selftest` 注入一个比公开攻击报告更强的信号（1.5 W × 10 ms
= 0.015 J 能量信号、3 MHz 频率偏移），并叠加安静环境噪声（对攻击者
最有利的近空闲同驻场景）。

检验设计：

| 统计量 | 含义 | 报警阈值 |
| --- | --- | --- |
| Welch t | 两类均值差异的 95% 显著性 | \|t\| ≥ 2 |
| Cohen's d' | 标准化效应量（攻击者信噪比） | ≥ 0.5 |
| Mann-Whitney AUC | 无分布假设的单阈值分类器 | 95% 显著 **或** \|AUC−0.5\| ≥ 0.15 |

**多重比较控制**：单通道至少 2/3 个检测器同时报警才判定为可利用。
每个独立 5% 检验都有假阳性，要求独立统计量一致可把假阳性率压到
约 0.7%（0.05² × 3 量级），与 TVLA 等侧信道评估中"重复独立采集均
显著才确认"的实践一致。

控制实验：

1. **原始 tick 级观察者**（等价于未防护的高频计数器接口）必须
   检测到注入信号（d' ≥ 1.2 且 AUC 显著）——证明检验本身有效；
2. **standard / strict 策略观察者**必须无任何可利用通道；
3. `powfence-attackcheck` 负对照：人为把 ε 调到 1000 的弱配置必须
   被报警，正确配置必须保持安静——证明检验既不漏报也不滥报。

典型结果（`-windows 250`，20 组种子全部通过）：

- 原始通道：能量 d' ≈ 1.3、AUC ≈ 0.82；频率 d' ≈ 2.9、AUC ≈ 0.97；
- standard：能量/频率 d' < 0.2、AUC 与 0.5 的差异不显著；
  6 窗口滚动均值误差 < 1%；
- strict：能量 d' < 0.1；频率为常量、AUC = 0.5。

## 5. 监控效用如何保留

- 拉普拉斯噪声均值为零，多窗口平均后相互抵消：6 窗口滚动均值的
  相对误差实测 < 1%，满足节能调度/容量规划的精度需求；
- 窗口、量化粒度、预算都是策略参数，可按租户 SLA 调档；
- `/v1/budget` 向租户公开剩余预算与窗口参数，便于其安排采集节奏。

## 6. 证据边界（本方案不覆盖什么）

诚实声明以下局限：

1. **有界影响假设的正确性依赖硬件表征**。若实测低估了 $\Delta$，
   signal_bounded 声明随之弱化。要求：(a) 表征覆盖最坏工况；
   (b) 保留 ≥3× 安全余量；(c) 新 CPU 代际重新表征；(d) 无法表征时
   退回 full_range 或 nominal-only。
2. **朴素顺序组合偏保守**。每小时 ε 预算的数字看起来大（360），
   是因为按 3600 个 1 秒窗口逐个记账。Rényi DP / 高级组合可以给出
   更紧的等效 (ε,δ) 声明，当前版本未实现，列为后续工作；台账接口
   已预留替换点。
3. **不覆盖缓存/时序/内存等其他侧信道**，也不覆盖攻击者拥有宿主机
   特权或能直接挂载 sysfs 的情形——后者必须靠 OS 权限隔离
   （见 HARDENING.md）阻断。
4. **不覆盖物理接触/带外功耗测量**（机柜 PDU、主板探针）。
5. **聚合窗口内的极端共址调度**：若攻击者能让受害者操作恰好占满
   整个窗口，信号占比上升；缓解手段是 strict 策略的 5 s 大窗口与
   宿主机调度分散，根本手段是敏感工作负载绑定独占核。
6. **噪声 RNG 的安全依赖宿主内核 CSPRNG**。若 `/dev/urandom` 失效
   或被篡改，DP 保证不成立；启动时种子化失败会直接拒绝启动。
7. 自测的统计"无显著差异"是**证据而非数学证明**：它证明在给定
   信号强度、样本量与种子集合下无法区分，配合第 2 节的形式化 DP
   声明共同构成保证，不应单独引用。

## 7. 版本化的参数变更纪律

任何对窗口长度、量化粒度、灵敏度、ε 的修改都必须：

1. 重新运行 `powfence-selftest` 与 `powfence-attackcheck` 并归档 JSON；
2. 在变更记录中引用新的组合预算计算；
3. 审计日志保留旧策略名，保证事后可追溯某次释放适用的参数集。
